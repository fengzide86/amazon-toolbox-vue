# 浏览器运行底座说明

本文档描述课赛通 KST 当前的单任务浏览器底座，供产品、脚本开发和验收使用。它不是“真实平台脚本已完成”的声明；目前内置工作流主要用于本地演示和比赛模拟平台，真实外部平台脚本仍须按清单逐个接入并验收。

## 运行边界

工具从列表进入工作台后，桌面端使用一个工作区 WebView 和一个 Runner。Web 端只展示本地演示或能力说明，不能启动桌面 Runner。真实 Live 任务仍必须同时满足授权、脚本清单、版本、允许域名和 Runner 协议检查。

脚本状态由目录配置提供：

| 状态 | 工作台行为 |
| --- | --- |
| `demo_ready` | 允许本地沙盒演示，不代表真实平台可执行。 |
| `browser_ready` | 允许打开浏览器并只读扫描页面；不允许填写、点击、提交。 |
| `script_not_ready` | 允许只读预检；页面展示“脚本开发中”，不生成成功记录。 |
| `script_ready` | 只有在授权和其他运行前检查都通过后，才显示真实执行入口。 |
| `blocked` | 显示阻断原因，不能开始任务。 |

当前 Runner 的预检命令是只读准备流程：准备浏览器、校验目标地址、导航、扫描页面结构并生成页面指纹。预检结果中的 `canStart` 只表示底座和脚本清单看起来满足条件，不替代真实启动授权；开始 Live 前仍必须重新获取并验证授权。

## 生命周期

单任务最多保留一个 WebView 和一个 Runner。正常状态为：

```text
idle → registering → ready → navigating → inspected
                                      ↘ running → waiting_user → completed
                                                     ↘ cancelled / error
```

关闭工作台、返回工具箱、切换路由或关闭窗口时，必须先停止正在进行的预检或任务，再释放浏览器和监听器。预检失败也必须释放 Playwright 上下文、沙盒和嵌入式浏览器连接；验收时应重复打开和关闭工作台，确认没有孤立进程或监听器。

## 脚本接入顺序

真实脚本按以下顺序推进，不把模拟步骤当作真实能力：

1. 只读页面扫描，保存页面结构和指纹。
2. 只读定位，确认选择器策略。
3. 填写非提交字段。
4. 在隔离模拟页面验证提交动作。
5. 增加结果核验规则。
6. 以 `live_beta` 进行受控试运行。
7. 完成真实验收后才标记为 `live`。

脚本清单至少应记录工具标识、脚本 Key、版本、输入字段、允许域名、页面步骤、成功核验、人工介入能力以及 Demo/单任务/批量支持范围。适配器只能访问比赛模拟平台允许域名；真实电商后台域名不会因为配置错误而被当作模拟平台执行目标。

## 本地验收

在仓库根目录执行：

```powershell
npm run typecheck
npm run test:unit -- src/tests/electron/automationWorkflow.test.ts
```

验收重点：

- 未就绪脚本可完成预检和页面扫描，但不会执行任何业务动作，也不会产生成功记录。
- 重复点击不会创建第二个 Runner 或第二个浏览器上下文。
- 预检、关闭、路由切换和窗口关闭都能在有限时间内释放资源。
- Demo 工作流继续可以完成本地沙盒流程。
- `script_ready` 之外的工具不显示“开始真实执行”。
- 真实脚本接入前，不对外宣称已接入亚马逊或速卖通真实后台。

发布前使用仓库现有的 `检查.bat full` 运行完整门禁；本文件不授权发布、部署或修改生产配置。
