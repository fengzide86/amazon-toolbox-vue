# 赛训工具箱 — 学员端一键使用方案

> 状态：已按商业验证产品定位落地。本文档是后续迭代的产品与前端验收基线。

## 1. 产品定位

赛训工具箱服务于参加跨境电商赛训的付费学员。它不是亚马逊真实业务后台，也不是课程学习系统。产品价值是把重复、容易出错的平台操作封装成脚本，让学员只做选择和点击。

学员的标准路径固定为：

```text
授权码登录 → 选择工具 → 一键启动 → 看系统自动处理
                         ↓
                 必要时完成一个人工步骤
                         ↓
              完成 / 重新执行 / 联系客服
```

## 2. 信息架构

学员端一级导航只有四项：

1. 工具箱：默认首页，承担核心转化与使用。
2. 使用记录：仅回答何时使用、结果如何、是否再次使用或联系客服。
3. 套餐与授权：说明当前套餐和可购买权益，不展示授权码技术字段。
4. AI 客服：自动开始会话，承接常见问题和失败上下文。

设备管理保留为账户级低频能力，不占一级导航。旧 Dashboard 仅做兼容跳转。

## 3. 工具箱验收规则

- 标题固定为“选择一个工具开始”。
- 不提供搜索、分类、统计卡片或引导教程。
- 每张卡只展示名称、一句用途和一个结果明确的动作。
- 可用工具：点击整卡后申请启动授权并打开工作台。
- 套餐未包含：整卡使用付费橙状态，点击进入对应套餐页。
- 维护中：按钮不可用，明确显示“暂时不可用”。
- 启动期间全页工具卡禁用，避免连点产生多次任务。
- 后端用语义错误码区分套餐、平台、设备和工具状态；普通 403 不得清空登录。

## 4. 自动处理工作台验收规则

学员只看到四段进度：准备环境、自动处理、检查结果、完成。内部脚本仍可保留任意数量的细步骤、重试次数和计时，但这些信息只用于日志和管理员排障。

状态和动作：

| 状态 | 用户文案 | 主操作 |
|---|---|---|
| 准备/运行 | 正在准备 / 正在自动处理 | 停止操作 |
| 等待用户 | 具体、单步的操作说明 | 我已完成，继续处理 |
| 完成 | 处理完成 | 再用一个工具 |
| 失败 | 本次操作未完成 + 问题编号 | 重新执行 |
| 停止 | 操作已停止 | 重新执行 |

运行时遮挡目标网页交互，防止学员误点；等待人工操作时解除遮挡。停止和未完成退出必须确认。失败转客服时自动携带工具、平台、运行编号和问题编号。

## 5. 套餐规则

- 工具是否可用以工具配置中的 `available_plans` 为主，套餐 JSON 权限可作为覆盖规则。
- 登录结果包含 `plan_code`，前端不依赖中文套餐名猜权限。
- Y199 作为赛期主推套餐，Y999 作为全程服务价格锚点。
- Y15 体验套餐必须至少有体验工具可用，避免付费后进入全锁状态。
- 套餐页展示用户权益语言，不展示 `code_prefix`、工具 ID 或权限 JSON。

## 6. 指标与公告边界

成功率、调用量、耗时、工具分布等指标继续在后端和管理员端保留，用于质量控制；学员端不展示，避免形成错误锚定和解释成本。

活动、版本更新默认使用非阻断页内横幅；系统异常和维护通知才允许使用弹窗。公告关闭状态按公告 ID 本地记忆。

## 7. 视觉基线

- Glacier Cyan 继续作为主视觉；亚马逊橙只用于套餐、锁定和付费转化。
- 工具卡三列布局，整卡点击，标题与动作具有明显层级。
- 工作台全屏，左侧目标网页、右侧 340px 业务进度。
- 动效只用于加载、当前步骤和点击反馈，并遵守 `prefers-reduced-motion`。
- 所有图标使用 `@lucide/vue`，不新增内联 SVG。

## 8. 发布前验证

- 前端单元测试覆盖默认路由、工具状态、单次启动、四段进度、等待用户、停止确认和套餐展示。
- Electron 协议覆盖 `USER_ACTION_REQUIRED` 与 `USER_ACTION_COMPLETED`。
- 后端测试覆盖套餐权益序列化、工具授权拒绝错误码和登录 `plan_code`。
- 构建通过后，至少人工验证一次：Y15 可用工具、Y15 锁定工具、维护工具、运行完成、运行失败转客服。
