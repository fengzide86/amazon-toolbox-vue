# 代理工作台与交付权限

本模块面向渠道代理销售与客户交付；代理不是 B 端代打团队账号，也不是内部运营账号。保持现有 C/B 产品授权、单 Runner、Demo/Live 边界及内部财务规则。

## 入口与权限

| 角色 | 入口 | 数据范围 | 主要动作 |
| --- | --- | --- | --- |
| 超级管理员（负责人） | 后台「代理与交付」 | 全部代理业务 | 管理代理、调整客户归属、确认收款、发放授权、处理售后、配置返佣比例与登记线下月结 |
| 渠道代理 `agent` | 独立代理工作台 | 所属代理的客户、订单、授权、售后与返佣 | 建档、提交订单、交付已发放授权、查看激活、提交售后、只读查看自身返佣账 |
| 内部运营 `operator` | 原运营后台 | 原权限范围 | 不新增代理审批权限 |
| 内部客服 `support` | 原客服后台 | 原权限范围 | 不新增代理数据权限 |
| C/B 客户 | 原用户端/批量工作台 | 自身授权与执行数据 | 原功能保持不变 |

不同代理的列表、详情、统计、搜索和导出均在服务端限定归属；仅隐藏前端菜单不能构成权限隔离。代理不能通过旧管理接口读取内部用户、公账支出、全量订单或进行收款审批。

## 首次启用

1. 在隔离测试库验证迁移，正式启用前按项目发布流程备份并执行 Alembic。
2. 超级管理员在「代理与交付」创建代理主体。
3. 在「后台账号」创建渠道代理账号并绑定代理主体；原三种内部角色不需要迁移为代理。
4. 代理登录后进入独立工作台。每个账号归属一个代理主体；同一主体下的账号共享主体业务，不是按员工隔离。
5. 代理被停用后无法继续访问工作台，但已发给客户的授权不自动吊销。

不自动创建真实代理账号，不预置通用密码，不把测试账号当成交付账号。

## 订单与授权流程

客户建档 → 选择后台有效套餐 → 提交待确认订单 → 负责人核实实际到账并确认收款 → 负责人发放授权 → 代理转交客户 → 查看激活情况。

- “确认收款”仅记录已核实的到账事实，不调用支付通道，也不自动扣款。
- “确认收款”与“发放授权”是两个独立动作；订单未收款不能发码。
- 一笔订单至多关联一份授权，重复发码返回同一份结果。
- 套餐金额与权益由服务端取值并保存快照；代理不可通过提交任意金额自行改价。
- 退款/延期售后只是申请与回复记录，不自动退款、延长授权或改变分润。
- 返佣比例由负责人按代理配置，未配置时不产生佣金；代理不能修改比例或确认结算。
- 不增加自动转账、提现、余额充值、代理库存或多级分销。
- 退款及取消订单保留历史，不作为可继续交付的订单呈现。

## 返佣与线下结算

- 负责人确认收款后，按该笔已确认订单金额与当时配置比例计提；金额和比例保存为独立快照，修改比例只影响后续收款，不追溯改写历史佣金。
- 售后申请本身不产生退款或佣金变化；负责人执行实际订单退款登记时，按原计提快照生成负向冲正，不覆盖或删除原记录。
- 负责人先预览月结，再确认登记；该操作只保存线下结算事实，不调用支付通道、不自动转账。
- 代理可只读查看待结算、已结算、累计计提、退款冲正及明细；服务端仍限定自身代理归属。

## 归属与历史数据

代理主体、客户、售后及员工/订单/授权关联由迁移 `20260921_agency_workspace` 建立，并为订单对应授权建立唯一关系；可选返佣比例、计提/冲正台账与月结记录由迁移 `20260922_agency_commission` 补充。

历史无归属数据保持无归属，不自动认领。负责人调整客户归属时，同一事务迁移该客户的订单、授权和售后；新建订单和发码必须依据当前归属，不采用过期页面中的归属。

客户转派不会转移已计提佣金的代理归属快照；后续退款仍冲正原代理账目，避免把历史佣金转给新代理或扣错对象。

## 时间兼容约定

已知按 UTC 保存的聊天、工单、设备创建时间，接口输出显式时区，浏览器按本地时间展示。数据库连接设置 UTC，避免新记录的数据库默认时间随环境漂移。

历史授权到期时间沿用服务端本地墙钟语义；本轮没有把所有历史到期时间强行当 UTC，也没有批量改写到期数据。新增代理授权和既有授权判断保持一致，并在返回到期时间时带出服务端时区。

## 配套用户体验修复

- 购买咨询读取真实公开联系方式；未配置时进入应用内咨询，不展示编造的微信号。
- 未说明问题时转人工会要求补充问题；用户确认后创建工单。
- 用户通过「我的工单」查看后台回复、刷新和翻页；请求失败可重试，旧请求不覆盖当前列表。
- B 端授权与设备数来自服务端，完成/取消批次不再继续显示待处理假状态。
- C/B 记录支持真实分页；Demo 可以再次准备，Live 不展示尚未实现的恢复能力。
- 演示画面显示有含义的示例并明确标记 Demo，不冒充外部平台真实执行。
- 登录资料与标签页会话绑定，避免同时打开负责人、代理及客户时串用显示身份。

## 技术边界与验证

服务位于 `backend/domains/commerce/agency.py`，路由位于 `backend/routers/agency.py`；事务由服务层负责。前端集中在 `src/features/agency/`，使用生成的 OpenAPI 类型与 Zod 运行时解析。

重点测试：归属隔离、旧接口拒绝代理、待确认/已收款/已交付流程、重复发码、客户转派、停用代理、退款后的统计与交付提示、详情旧请求竞争、三种角色同时登录、迁移历史数据保持。

本地未提交改动、Web 构建和解包桌面目录不属于正式发布。正式发布需新版本、已推送且通过 CI 的唯一提交、迁移与回滚准备，以及真实安装器验收；不得以相同的现有版本号覆盖线上制品。
