## 1. 范围与边界

本次从已登录的 V2 页面进入 `SellerProductCategory`，再进入 `SellerProductCreate`（添加商品）。同时读取页面加载的前端 JavaScript 静态资源，分析其请求地址、字段名、校验和评分展示逻辑。

没有调用保存或提交接口，没有上传文件，没有写入商品、订单、广告或店铺数据；浏览器中的令牌、Cookie、加密参数和账号信息均未记录到资料中。

这份地图是“当前前端实现中确认到的协议线索”，不是对所有页面或所有类目的最终字段承诺。类目属性由服务端动态返回，必须在后续获得明确的测试类目后继续只读采样。

## 3. 共享网络与请求传输

### 3.1 共享传输层

V2 页面通过共享 `AjaxSend` 发起 POST 请求。前端会：

1. 将业务参数放入 POST body；
2. 从当前 URL 的 `paras` 读取加密页面上下文；
3. 在请求 URL 中继续携带加密的 `paras`；
4. 从浏览器本地存储读取登录令牌，并以 Bearer Authorization 头发送。

因此后续接入不能只复制某个按钮的请求体，还要同时保持页面上下文、登录态、课程/店铺上下文和语言参数，否则容易出现“页面能打开但保存无效”或返回权限错误。

### 3.2 已确认的请求风格

共享布局脚本会解析并继续传递 `courseId`、`shopId`、语言及若干业务上下文。页面之间通过加密参数导航，不适合把地址中的参数当作固定常量写死。

## 4. 类目选择接口

来源：`SellerProductCategory.js` 静态逻辑。

### 4.1 读取类目

- POST `../ECrossAmazon/GetProductCategory`
- 主要请求字段：`CLevel`、`browsePath`
- 前端读取字段：`CID`、`PID`、`CLevel`、`CPath`、`isSellable`、`authorized`、`browsePath`、`productType`、`NameEN`、`NameCN`

### 4.2 类目搜索

- POST `../ECrossAmazon/GetProductCategorySearch`
- 主要请求字段：`keyword`

### 4.3 类目是否可添加商品

- POST `../ECrossAmazon/SearchIsCanAddPruduct`
- 主要请求字段：`courseId`、`shopId`、`optype: 1`、`language`

通过检查后，前端才会导航到 `SellerProductEdit`，并传递 `categoryId`、`proId`、`index`、`followup`、`ds2001Foll`、`ds2302Foll` 等加密上下文。

## 5. 新商品搜索与商品列表接口

来源：`SellerProductCreate.js` 静态逻辑。

### 5.1 搜索/列表

- POST `../ECrossAmazon/GetSellerProductList`
- body 中有 JSON 字符串 `arrayStr`
- `arrayStr` 当前由以下条件组成：`productStatus: 1`、`searchType`、`keyword`、`productType: 0`、`page: 1`、`pageSize: 10`、`language`

### 5.2 列表展示字段

当前前端渲染过的字段包括：

`DS2001`、`DS2013`、`DS2048`、`DS2024`、`DS20169`、`DS20170`、`DS2301`、`DS2302`、`DS2312`、`DS2326`、`DS2327` 等。

静态脚本只证明这些字段会被前端读取或展示，不证明它们在当前账号或每个商品上一定有值。

## 6. 编辑页读取与保存接口

来源：`SellerProductEdit.js` 静态逻辑。

### 6.1 读取

- POST `../ECrossAmazon/GetProductAllList`
- 主要请求字段：`courseId`、`shopId`、`categoryId`、`DS2001`、`language`
- 返回被拆成多个 JSON 字符串，前端分别绑定产品编号、运费模板、分类面包屑、动态属性和已有产品数据。

### 6.2 保存边界（仅分析，未调用）

- POST `../ECrossAmazon/SaveProduct`
- body 主要是 JSON 字符串 `arrayStr`
- 其中包含产品基础 XML、动态属性 XML、变体 XML、描述关键词 XML、Keywords XML 以及 `oPType`（暂存/提交）等字段。

前端另有 `SaveProductSku` 字样和 SKU 相关逻辑，但本轮没有触发保存流程，也没有验证服务端是否在当前版本单独暴露该调用。

## 7. 字段矩阵（已从静态前端确认）

### 7.1 身份、标题与 SKU

| 字段 | 当前可确认的用途 |
|---|---|
| `DS2001` | 产品内部编号/当前产品上下文 |
| `DS20169` | 外部产品编号 |
| `DS20170` | 外部编号类型，前端包含 GTIN/EAN/GCID/UPC 判断 |
| `DS20171` | 品牌 |
| `DS2024` | 商品标题 |
| `DS2083` | 产品编号/SKU；提交前不能为空 |
| `DS2013`、`DS2301`、`DS2302` | 产品/变体上下文，列表与变体 XML 会读取 |

### 7.2 商业、库存和履约

以下字段在前端保存、回填或校验逻辑中出现；精确中文标签仍应以指定测试类目的动态返回为准：

`DS2071`（价格相关）、`DS2061`（运费模板）、`DS20178`、`DS20184`、`DS20192`（配送/履约相关）、`DS20189`、`DS20190`（商品服务选项相关）、`DS20179`、`DS20180`（数量/库存相关）、`DS20187`、`DS20191`（日期校验）、`DS2045`、`DS2069`（变体或履约状态联动）。

前端已确认 `DS20179` 最大值为 99999；补货日期和开始销售日期会经过日期校验。选择变体时会联动部分履约字段并清零某些状态值。

### 7.3 内容与质量评分

动态属性按服务端返回的 `AID`、`title`、`helptext`、`types`、`Exp`、`cataAttrsValues` 等模型渲染，属性按 `nav` 分到 Description、Keywords、More Details 三个区域。

固定或半固定的内容字段包括：

- `DS2050`：简要描述/Description；
- `DS2088`：Bullet Point 或 Key Product Features 五项关键词；
- `DS2094`：Keywords；
- `DS2089`、`DS2090`、`DS2091`、`DS2095`、`DS2096`、`DS2097`：评分分项；
- `DS2021`：综合分。

### 7.4 重量与尺寸

前端将动态属性中的以下英文属性名归一到固定字段：

- 重量：`Shipping Weight` 或 `Weight` → `DS2053`；
- 长、宽、高：Package Dimensions、Item Dimensions、Item Display Dimensions 的不同命名变体 → `DS2058`、`DS2059`、`DS2060`；
- 同时记录重量单位 `Weight_unit` 与尺寸单位 `Volume_unit`。

如果包装尺寸存在，前端优先使用包装尺寸；否则回退到商品尺寸。非数字值会被归零，这一点后续做导入校验时必须显式提示，不能静默当成有效的 0。

### 7.5 动态类目属性控件

当前静态脚本支持这些控件类型：

- `textarea`：最多 2000 字符；
- `money`：两位小数金额输入；
- `text`：最多 500 字符；
- `datetime`：日期输入；
- `select`：服务端选项；
- `number`：0–9999；
- `boolean`：复选框；
- `text/select`：有选项时下拉，否则文本框；
- `text+select`：数值与单位组合。

是否必填由服务端模型与页面的 required class 决定，不应从字段名猜测。字段的 `helptext` 和 `Exp` 是后续生成“填什么、为什么、如何得分”提示的主要来源。

### 7.6 变体字段

变体 XML 当前收集：

`DS2301`、`DS2302`、`DS2309`、`DS2310`、`DS2324`、`DS2325`、`DS2312`、`DS2326`、`DS2327`、`DS2328`、`DS2329`、`DS2305`、`DS2330`、`DS2331`、`DS2332`、`DS2306`、`DS2339`、`DS2320`。

提交前会检查：至少有一条变体、变体必填值完整、SKU 不重复、数量和价格范围有效。SKU 重复是前端明确拦截的错误。

## 8. V2 当前评分口径

在 `SellerProductEdit.js` 的评分展示逻辑中，前端明确写出了以下权重：

```text
综合分 = 标题 25% + 图片 20% + 重量 10% + 尺寸 10% + 发货期 5%
       + 描述 10% + Bullet Point/Key Product Features 五个关键词 15%
       + Keywords 5%
```

评分字段对应关系：

| 评分项目 | 字段 |
|---|---|
| 综合分 | `DS2021` |
| 标题 | `DS2089` |
| 图片 | `DS2091` |
| 重量 | `DS2095` |
| 尺寸 | `DS2096` |
| 发货期 | `DS2097` |
| 描述 | `DS2090` |
| 五个 Bullet/Key Product Features | `DS2088` |
| Keywords | `DS2094` |

这说明打法不能只围绕标题和关键词；重量、尺寸、发货期合计 25%，图片占 20%，是容易被忽视但明确计分的部分。最终得分仍以平台返回的真实分项值为准，不根据权重自行伪造满分。

## 9. 前端校验与业务风险

当前已确认的校验包括：

- 至少一条变体；
- 变体名称不能为空；
- 必填动态属性不能为空；
- SKU 不能为空且变体内不能重复；
- 至少上传一张产品图片；
- 最大订单商品数量不超过 99999；
- 补货日期、开始销售日期需通过日期校验；
- 包装重量、长宽高限制为最多 10 位整数和 2 位小数；
- 变体数量与价格有 0–99999 范围校验。

需要重点防止两类误判：

1. 页面上有控件不代表该控件在当前类目计分；
2. 前端没有报错不代表服务端一定接受，保存结果必须有明确回读或列表状态确认。

## 10. 结论：现在“懂到了什么”

### 已确认

- V2 的页面分区、核心读接口、保存入口和共享请求风格；
- 产品身份、SKU、描述、图片、重量、尺寸、发货期、关键词和变体字段族；
- 综合分及八项评分权重；
- 动态属性由服务端按类目返回，前端负责渲染和收集。

### 尚未确认

- 指定类目在当前账号下实际返回的 `AID`、字段标题、可选值和必填状态；
- 哪些动态空项在该类目真正参与得分；
- 服务端保存成功响应的完整结构及保存后回读结果；
- 库存、订单、广告、品牌、增长、数据报告和绩效各页面的完整字段与接口；
- 当前账号的真实网络请求结果，因为本轮没有从外部脚本直接复用浏览器认证态调用业务接口。

## 11. 下一步建议（仍不写脚本）

1. 选定一个明确的测试类目和一个平台允许查看的测试商品，仅做页面读取，采集该类目的完整动态属性清单；
2. 把每个 `AID` 建成“字段字典”：字段名、控件类型、单位、是否必填、是否计分、示例值、错误提示来源；
3. 对照旧资料的物流、商品发布、订单处理、营销和 FBA 字段，建立旧字段 → V2 字段的映射表，不直接复制选择器；
4. 对每个字段先做“草稿预览/本地校验/只读评分展示”，待规则确认后再讨论脚本的填充与提交策略；
5. 网络接口方面优先记录请求时序、响应结构和错误码，不保存令牌或客户数据，不把加密 `paras` 固化进脚本。
